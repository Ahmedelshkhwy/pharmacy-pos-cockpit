{% if ar %}الخطة بتتحسب إزاي{% else %}How the plan is calculated{% endif %}

{% if ar %}

قيمة التحويل = الخسارة اللي بيمنعها عند الفرع المستلم لحد ما طلبية المورد توصل (احتمال البيع × الربح وخسارة الزبون) + البضاعة اللي صلاحيتها قربت عند الباعت + {{ '%g' % settings.release_value_percent }}% من قيمة الراكد اللي بيتحرك.

العربية مالهاش حد للحمولة، فلو رايحة من فرع لفرع بتشيل كل أصنافهم مع بعض. الأداة بتختار الفروع والترتيب اللي يجيبوا أكبر قيمة ناقص تكلفة الكيلومترات، جوه وردية السواق، والتحميل دايماً قبل التسليم. ولو عدّت على فرع مرتين في نفس اليوم بيجيب قيمة أكبر، بتعمل كده.

{% if plan.method in ("exact", "exact+") %}الفروع قليلة، فالخطة دي اتثبت إنها الأحسن رياضياً (HiGHS){% if plan.method == "exact+" %}، وزيارة فرع مرتين حسّنتها كمان{% endif %}.{% elif plan.method == "search" %}الفروع كتير، فالخطة دي نتيجة بحث منظّم بعدد خطوات ثابت، فنفس البيانات بتطلّع نفس الخطة دايماً.{% endif %} المسافات تقديرية من الخريطة، إلا اللي اتكتب بالإيد.

{% else %}

A transfer's value = the loss it prevents at the receiving branch until a supplier order could arrive (chance of selling × profit and customer loss) + stock about to expire at the sender + {{ '%g' % settings.release_value_percent }}% of the idle stock it moves.

The vehicle has no load limit, so going from one branch to another carries all their items together. The tool picks the branches and order with the highest value minus the cost of kilometres, within the driver's shift, always loading before unloading. If visiting a branch twice in a day is worth more, it does that.

{% if plan.method in ("exact", "exact+") %}With few branches this plan is proven best (HiGHS){% if plan.method == "exact+" %}, then improved by a second visit{% endif %}.{% elif plan.method == "search" %}With many branches this plan comes from a structured search with a fixed number of steps, so the same data always gives the same plan.{% endif %} Distances are map estimates unless entered by hand.

{% endif %}
